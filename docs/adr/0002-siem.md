# 0002. Elección de Wazuh como SIEM de comparación

Fecha: 2026-08-18
Estado: Aceptado como comparación opcional del MVP

## Contexto

Uno de los objetivos de investigación de HoneyTrace es comparar su capacidad de reconstrucción de ataques contra la de un SOC tradicional. Para eso se necesita un SIEM open source que pueda recibir la misma telemetría que HoneyTrace y generar alertas de forma independiente.

## Decisión

Se elige **Wazuh** como SIEM inicial de comparación.

## Alternativas consideradas

- **Wazuh**: open source, agente ligero (compatible con Raspberry Pi), buena documentación, integración estándar con logs y agentes de host.
- **ELK/OpenSearch + reglas propias**: mayor flexibilidad pero mayor esfuerzo de configuración y mantenimiento, y consumo de recursos más alto para el hardware disponible.
- **Otros SIEM comerciales**: descartados por costo y por no alinearse con el carácter open source / reproducible de la investigación.

## Consecuencias

- Wazuh se integra recibiendo telemetría en paralelo al pipeline de HoneyTrace (ver `docs/arquitectura/flujo-de-datos.md`), no como parte del pipeline de reconstrucción.
- Los resultados de Wazuh (alertas) se usan únicamente como línea base de comparación en `docs/investigacion/metodologia.md`, no como dependencia funcional de HoneyTrace.
- Si el consumo de recursos de Wazuh en la Raspberry resulta excesivo (RNF-01), se evaluará ejecutar el Wazuh manager en un host separado y dejar solo el agente en la Raspberry; esto se documentaría como una actualización de este ADR o uno nuevo.
