# Definition of Ready (DoR)

Una issue puede entrar a un sprint cuando cumple:

- [ ] Título claro y descripción con contexto suficiente para empezar sin preguntas bloqueantes.
- [ ] Componente identificado (Honeypot, Collector, Normalizer, Engine, SIEM, API, Frontend, Docs).
- [ ] Criterios de aceptación explícitos y verificables.
- [ ] Dependencias identificadas (otras issues, ADRs, esquemas de `/schemas`).
- [ ] Estimación acordada por el equipo (story points).
- [ ] Si afecta una decisión de arquitectura: referencia al ADR correspondiente (existente o a crear).
- [ ] Si es una tarea de investigación: referencia a la pregunta de investigación que atiende (`docs/investigacion/preguntas-de-investigacion.md`).
