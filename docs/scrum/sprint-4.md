# Sprint 4 — Integración, campo y cierre

## Duración

6–10 de septiembre de 2026.

## Objetivo

Congelar el MVP, ensayarlo, ejecutar la prueba autorizada en OTI UNI y preservar evidencia reproducible.

## Backlog por fecha

- [ ] **6 sep — Equipo:** congelar alcance; API de consulta y frontend serán mínimos y no desplazarán seguridad ni evaluación.
- [ ] **6–7 sep — IA:** ejecutar regresión completa y organizar fixtures, ground truth y resultados.
- [ ] **6–7 sep — IB:** validar kit físico, fuente, cables, SSD, adaptador, temperatura y devolución.
- [ ] **8 sep — LT:** dirigir ensayo de 4 horas con fallos inducidos y verificar márgenes de Raspberry Pi.
- [ ] **8 sep — LT:** ejecutar revisión de seguridad y confirmar que no existe acceso a host o red fuera de alcance.
- [ ] **9 sep — Equipo:** reunión Go/No-Go y firma de checklist.
- [ ] **10 sep, 09:00–13:00 — Equipo + OTI UNI:** ejecutar la prueba controlada si fue autorizada.
- [ ] **10 sep — IA:** mantener bitácora y evidencia funcional.
- [ ] **10 sep — IB:** monitorear recursos, conectividad, almacenamiento e inventario.
- [ ] **10 sep — LT:** controlar cambios, comunicación y decisión de detención.
- [ ] **10 sep — Equipo:** apagar, retirar, verificar cierre de puertos, respaldar y obtener constancia de cierre.

## Criterio de salida

La prueba termina sin impacto institucional, con evidencia íntegra, inventario cerrado y resultados suficientes para responder las preguntas de investigación. Si hay No-Go, se documentan las causas y se ejecuta el experimento equivalente en laboratorio.

## Funcionalidad que no bloquea el hito

Visualización 3D, interfaz pulida y Wazuh completo son extensiones. Solo se incluyen si el pipeline, la evaluación, el aislamiento y el hardware ya cumplen la Definition of Done.
